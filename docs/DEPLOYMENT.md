# Публикация через GitHub и Netlify

Репозиторий: https://github.com/that-cell/hronika-ege

Рабочая ветка платформы: `feat/unified-learning-platform`. Отправлена в GitHub. Основная ветка не изменена.

## Конфигурация

В `netlify.toml` заданы Node.js 22 и каталог публикации `dist`. Перед сборкой выполняются 35 тестов и валидация материалов. Команда сборки копирует только файлы сайта, исходные учебные данные и браузерные модули; локальные сохранения, инструменты разработки и Git-архив в публикацию не попадают.

Новая платформа: https://trajectory-ege-that-cell.netlify.app

Автообновление подтверждено production deploy `6ae32b3ac16775d219950052`, состояние `ready`, commit `6b29b6416c47cdcf4530acb8c6e9c3885da3b1be`. По отдельному явному подтверждению пользователя новый сайт сделан публичным (`sso_login: false`). Главная и `/release.json` отвечают HTTP 200 без входа и перенаправления. Старый сайт не затрагивается.

Netlify project ID новой платформы: `4a1e4557-5019-477b-8518-5593b8c880ba`. Производственная ветка: `feat/unified-learning-platform`. Новый сайт отдельно подключён к GitHub.

Старый сайт https://chipper-crisp-5460c4.netlify.app сохранён отдельно: production branch `main`, исходный commit `8f42803202208454669252222adf74d88188bade`, исходные команды сборки и каталог публикации. Он был кратковременно переключён на новую платформу, затем по уточнению пользователя полностью возвращён к исходной версии. Новые изменения платформы не публикуются на старом сайте.

Обновления новой платформы отправляйте в указанную ветку. Ветку `main` не меняйте: она обслуживает старый сайт. Диагностический файл `/release.json` нового сайта показывает commit и ветку опубликованной сборки.

Netlify CLI установлен отдельно в рабочие инструменты этой сессии, а не в зависимости платформы. Авторизация проходит через официальный браузерный запрос; ключи не добавляются в репозиторий.

## Обновления

После подключения Git изменения отправляются в выбранную ветку. Netlify получает обновление, запускает тесты, собирает статические файлы и публикует успешную версию. Изменение домена не переносит localStorage: пользователю нужно экспортировать и импортировать свой профиль. Обновление на том же адресе сохраняет локальные данные браузера.
